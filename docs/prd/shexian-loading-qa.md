# 加载速度验收

目标：冷缓存从导航开始，5 秒内完整三维古城已渲染、可旋转和切换景点，不以静态预览或文字出现替代。

2026-10-08，本机现有独立 Chrome、生产构建：关闭浏览器缓存，10 Mbps 下行、80 ms 延迟。

| 条件 | 三次首次完整渲染时间 |
| --- | --- |
| 桌面 1440px，CPU 不降速 | 3.627 / 3.602 / 3.599 秒 |
| 手机 390px，CPU 4 倍降速 | 4.136 / 3.743 / 3.831 秒 |

同条件旧版手机基线 12.785 秒。最终加入运行时几何一致性检查后，无 hash 的全城入口为 3.820 秒（手机，4 倍 CPU 降速）。

实现：整城与钟楼在发布前完成布局修正、静态合并和压缩；主文件从 11,789,236 + 349,036 字节降到 3,429,336 字节。浏览器不再展开约 3,846 个原始 Draco 片段或执行布局修正。实际渲染网格为 148。总览从约 1.1 MB PNG 改成 34,392 字节 WebP；提前下载主模型。

校验：原始导出 575,221 个三角片，压缩后 575,154；仅清理退化三角片，未使用简化器。全城边界最大偏差 0.0032654 米。保留全部八个景点边界、既有修正、24 张材质图。运行时核对模型实际网格与三角片数。八章切换无报错、390px 无横向溢出。博物馆手机截图及钟楼桌面截图位于 qa/。

复现：启动本地开发页 `?bake=1`，等待 `cityJournal.loaded`；在开发页调用 `import('/src/bake-city.js').then(m=>m.bakeCity())`；运行 `node prepare-city.mjs`、`node verify-prepared.mjs` 和构建。原始烘焙文件保存在 outputs/prepared-city，不发布；发布目录只保留已准备模型。`perf-environment.mjs` 只连接已经获批的独立 Chrome，以关闭缓存、限速及 CPU 降速建立测试环境，不启动其他浏览器。结束会恢复设置。

边界：5 秒结论适用于上述测试网络和设备条件；断网、极低带宽、GitHub Pages 链路异常不能以代码保证。线上结果另行验收，不用本地结果冒充线上实测。
