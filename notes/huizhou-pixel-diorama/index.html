从 OSM 到 4K 动态像素沙盘：徽州古城 3D 等轴测重建全流程

一、整体管线：为什么不直接“文生图”？

如果直接用图像模型生成古城鸟瞰图，最大的问题是空间拓扑失真：道路接不上、牌坊与城门比例失衡、桥面和河岸对不上真实地形，后续几乎无法叠加真实的车流、行人与遮挡关系。

因此整个工程拆成五个严格对齐像素坐标系的阶段，所有阶段共用同一套局部三维笛卡尔坐标系与 45° 正交等轴测投影矩阵：

阶段 核心输入 关键产出
1. 路网与高程 OSM Overpass + Copernicus GLO-30 (30m) 交叉口打断、≤3m 重采样 3D 路网与等轴测投影
2. 三维白模与精模 714 栋建筑（含天井）+ 5 座 Meshy 精模 Blender 5.2 渲染的 4K 五通道控制图（高程/深度/语义等）
3. 4K 像素底图合成 五通道控制图 + 地标局部精修 4096×4096 正交像素底图（含许国石坊与钟楼校准）
4. Web 动态沙盘打包 4K 底图 + 16-bit 世界高程 + 语义掩模 7.5 MB 纯静态沙盘包（DZI 瓦片 + WebGL2 + IDM 路网）

二、地理底盘：OSM 拓扑打断与 GLO-30 高程贴合

研究区锁定在徽州古城核心区（29.8600°N ~ 29.8730°N，118.4280°E ~ 118.4420°E）。抓回 OSM 道路与水系后，先在同高程层完成交叉口拓扑打断，并以不超过 3.0 m 的步长均匀重采样；随后按需通过 HTTP Range 读取 AWS Open Data 上的 Copernicus GLO-30 COG GeoTIFF 瓦片，用单调钳制 Catmull-Rom 双三次插值为每个路网节点赋予高程。

针对跨练江的太平桥等桥梁，如果直接贴合 30m 粗粒度 DEM 会出现桥面下陷。管线对桥梁段做了独立的高程平滑与桥面防下陷处理，再统一投影到方位角 45°、倾角 45° 的正交等轴测画布上。

三、Blender 5.2 五通道渲染与核心地标校准

有了精确路网后，我们从 OSM 提取了 714 栋建筑轮廓（保留徽派民居特有的天井 multipolygon 内洞）与古城墙，并在 Blender 5.2 中融合 5 座核心历史地标（许国石坊、东谯楼、南谯楼、徽州府衙仪门与正堂）的带贴图 3D 精模，输出严格对齐 4096×4096 像素的五通道控制图：Clay、Depth Z、Height AGL、Normal 与 Semantic Mask。

在后续像素重绘与人工走查中，重点修正了两个影响观感的关键细节：一是将许国石坊（八脚牌坊）从原先偏小的比例放大并恢复八柱口字形结构；二是将位于 Y 字街口的中和街钟楼向右旋转对齐至面朝中和街（+17° ENE），确保地标朝向与真实街景一致。

四、Stage 5：把 4K 像素图变成可交互的动态沙盘

定稿的 4K 像素底图本身是一张静态画。为了让它在浏览器里“活”起来且不依赖任何后端服务，离线构建脚本 build_web_diorama.py 生成了四个互相咬合的图层：

  • 13 级 DZI WebP 瓦片金字塔：将 4096×4096 底图切分为 94 张 512×512 WebP 瓦片（共约 5.0 MB），由本地化部署的 OpenSeadragon 4.1.0 驱动，兼顾秒开与 5 倍以上细节放大。
  • 练江 WebGL2 有机水波着色器：利用语义掩模提取 2,991,787 个水体像素并降采样为 2K 精确岸线掩模，配合各向异性二维值噪声（hash21 + vnoise）在练江表面生成随 45° 视角拉伸的柔和波纹与岸边衰减，避免传统正余弦叠加产生的规则圆点阵列，同时确保太平桥十六孔石墩与草坡零溢出。
  • 干道车流与古巷行人分离：OSM 中古城内部分街巷（如中和街、斗山街、十字街）被标为 motor_local。我们在构建期将机动车严格限制在 motor_arterial 干道（生成 200 条分向靠右车道与 11 个 20m 逻辑信号路口，采用 IDM 跟驰模型 + 12 秒防死锁机制），而把古街巷与步行道（171 条）全部交给行人，杜绝汽车穿行牌坊和深巷的违和感。
  • 45° 等轴测高度前景遮挡层：这是最关键的立体感来源。沿着屏幕纵轴 Y，正交相机射线深度满足线性关系 depth_key = ele + (√2 / PX_PER_M_4K) · Y。只有当建筑像素（白墙、青瓦、马头墙、地标）同时满足视线深度与高程阈值高于周边路面时，才写入前景遮挡层（共 115,117 px，其中许国石坊 1,388 px、东谯楼 1,068 px、南谯楼 1,504 px、太平桥面中心 0 px）。这样车辆与行人穿过牌坊和城门洞时会被屋檐自然遮挡，而走在北侧白墙前的行人不会被误切。

五、纯静态交付与性能表现

整套 Web 沙盘打包后总计 7.5 MB，不依赖外部 CDN 或后端接口，可直接托管在 GitHub Pages 上。在浏览器实机测试中（1.45× 全局概览与 3.53× 太平桥近景），43 辆车与 108 名行人同时运行，帧率稳定在 60–160 FPS，Console 与 WebGL 零报错。
