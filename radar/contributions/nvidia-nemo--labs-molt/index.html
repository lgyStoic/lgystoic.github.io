实现 OrcaRouter 评估节点支持

Issue #104 · [feature] OrcaRouter provider support for Molt ↗

目标：在 Molt 中添加 OrcaRouter 作为可选的 OpenAI 兼容 provider，用于 LLM-as-judge 评估，并提供示例和文档。

为什么值得长期做：扩展 Molt 的 Agentic 评估生态，熟悉 Molt 的 `ChatAgent` 和 `Env` 接口，是深入理解其 Agentic-first 设计的绝佳切入点，有助于未来主导更多评估模块的开发。

第一步：在 Issue #104 中回复维护者，确认是否需要封装一个专门的 helper 类，还是仅在文档和示例中展示如何配置现有的 `AsyncOpenAI` 客户端。
大致实施方案
  • 调查 Molt 当前的 `ChatAgent` 和 `Env` 实现，定位 OpenAI 客户端的初始化位置。
  • 如果维护者同意添加 helper，编写一个轻量级的 OrcaRouter 客户端封装，继承或包装现有的 OpenAI 客户端逻辑。
  • 在 `examples/` 目录下添加一个使用 OrcaRouter 作为 LLM-as-judge 的示例脚本。
  • 更新文档（如 `README.md` 或 `AGENTS.md`），说明如何配置 OrcaRouter 的 `base_url` 和 API Key。
  • 编写单元测试，使用 mock 验证客户端的请求格式和路由逻辑。
可能涉及的目录或文件
  • molt/agents/
  • examples/
  • AGENTS.md
  • README.md
验收方式
  • 运行新增的单元测试通过。
  • 使用 mock server 运行示例脚本，验证请求成功发送到指定的 base_url 且格式符合 OpenAI 规范。

编写 DeepSeek-V4 RL 多节点启动与环境配置脚本

Issue #10 · [feature] Roadmap for DeepSeek-V4 RL training support (DSA/MLA kernels, mixed precision, GPU footprint, and the agentic environment path) ↗

目标：提供一键式环境设置脚本、DeepSeek-V4-Flash 的训练配置模板，以及 SLURM/Ray 多节点启动脚本。

为什么值得长期做：解决大模型在集群部署中的痛点，直接贡献于 Molt 的核心竞争力（Frontier-scale MoE），展现 AI Infra 专长，为后续主导分布式训练架构优化铺平道路。

第一步：在 Issue #10 中回复，提出先贡献环境配置脚本和 SLURM/Ray 启动脚本的 PR，询问维护者对 vLLM 版本和 CUDA 依赖的具体要求。
大致实施方案
  • 编写环境初始化脚本（如 `scripts/setup_env.sh`），处理 transformers, vLLM, TransformerEngine 等依赖的版本冲突，特别是针对 CUDA < 13 的降级编译逻辑。
  • 在 `examples/` 或配置目录中，创建针对 DeepSeek-V4-Flash 的训练配置模板，预设 TP=1, PP/EP/CP 拓扑，以及 fp8 混合精度参数。
  • 编写 SLURM `sbatch` 脚本和 Ray 多节点启动脚本，处理网络接口检测、Ray head/worker 启动同步、端口冲突避免及环境变量（如 `PYTHONPATH`）传递。
  • 提交 PR 前，在本地或无 GPU 节点上进行脚本的 dry-run 测试，确保语法和逻辑正确。

修复 SFT 训练中的 Checkpoint Metadata 形状不匹配 Bug

Issue #90 · [bug] Quickstart Qwen3.6 SFT crash with metadata shape mismatch ↗

目标：修复在开启 Activation Checkpointing 时，前向传播和重计算期间张量形状不匹配导致的崩溃。

为什么值得长期做：深入 Molt 的 FSDP2 和 AutoModel 训练后端，解决核心的显存优化（Activation Checkpointing）问题，是证明底层 Infra 能力并成为核心维护者的关键一步。

第一步：在 Issue #90 中留言，说明自己熟悉 PyTorch Infra，正在分析 PyTorch issue 166926，并询问是否能在小模型上复现该问题。
大致实施方案
  • 仔细阅读 PyTorch issue 166926，理解 FSDP2/Checkpointing 在特定操作（如 view, reshape 或特定算子）下导致 metadata 变化的原因。
  • 审查 `molt/trainer/fsdp/strategy.py` 和 `molt/trainer/sft_trainer.py`，特别是与 `torch.utils.checkpoint` 相关的调用。
  • 检查模型前向传播中是否有依赖于动态形状或在重计算时会发生变化的随机操作（如 sequence packing 导致的形状截断）。
  • 编写一个极简的单机 CPU/单 GPU 测试脚本，模拟 SFT microbatch 的输入形状，尝试触发 `CheckpointError`。
  • 根据 PyTorch 社区的 workaround 或修复方案，在 Molt 的 FSDP 策略中应用补丁（例如调整 checkpoint 的 `use_reentrant` 参数，或修改张量视图操作）。
可能涉及的目录或文件
  • molt/trainer/fsdp/strategy.py
  • molt/trainer/sft_trainer.py
  • molt/cli/train_sft.py
验收方式
  • 构造一个包含 activation checkpointing 的小规模单元测试，确保 forward 和 backward 成功执行且不抛出 CheckpointError。
开工前问题与风险

向维护者确认

  • 是否可以在不使用 B200 和 35B 模型的情况下，用较小的 Qwen 模型在单卡上复现此问题？
  • 目前 FSDP2 的 activation checkpointing 是使用 reentrant 还是 non-reentrant API？

风险

  • 该 Bug 可能深埋于 PyTorch 或 AutoModel 底层，如果无法在 Molt 层面 workaround，可能需要向上游提交修复。
