修复 Qwen3.6 SFT 时的 Activation Checkpointing Metadata Mismatch

Issue #90 · [bug] Quickstart Qwen3.6 SFT crash with metadata shape mismatch ↗

无人认领3 条评论bug更新 2026-09-10

用到的专长：深入理解 PyTorch 显存优化、Activation Checkpointing 及分布式训练底层机制。

目标：修复 `sft_qwen3_6_35b.sh` 运行时的 `CheckpointError`，确保前向传播和反向重计算时的张量 shape 完全一致。

为什么值得长期做：解决大模型训练中 FSDP2 与 Activation Checkpointing 结合时的底层张量元数据不一致问题，是深入 Molt 训练引擎核心逻辑的绝佳切入点。

怎么介入：Issue 处于 open 状态，虽有 linked PR #91 但已 closed，当前无活跃 assignee，适合直接介入。
第一个 PR 的边界：仅修复 checkpointing 时的张量元数据不一致问题，不涉及其他功能重构。
第一步：租用单卡 A100，运行复现脚本，定位导致重计算时 shape 发生偏移（如 1296 变 1297）的具体算子或 padding 逻辑。
认领留言（英文，可直接贴到 Issue）
Hi, I'm a PyTorch performance engineer and would like to look into this checkpointing metadata mismatch. The dimension shift (1296 vs 1297) strongly suggests an issue with sequence packing or padding masks not being deterministically restored during the recomputation phase. I plan to reproduce this on a single A100, trace the specific tensors to identify the operator causing the shape divergence, and ensure the correct context is preserved for `torch.utils.checkpoint`. Could you share if there was a specific reason PR #91 was closed? I can aim to submit a fix within a few days.
大致实施方案
  • 租用 A100 实例，拉取代码并运行 `MODEL_PATH=Qwen/Qwen3.6-35B-A3B bash examples/scripts/quick_start/sft_qwen3_6_35b.sh` 复现报错。
  • 检查 `molt/trainer/fsdp/strategy.py` 和 `molt/trainer/sft_trainer.py` 中的 checkpointing 包装逻辑。
  • 追踪报错中 position 72-77 的张量，对比前向传播和反向传播重计算时的输入维度（1296 vs 1297），这通常是由于 sequence length padding 或 packing 掩码在重计算时未正确恢复导致的。
  • 修复 padding/packing 掩码的传递，或在 checkpoint 包装器中显式保存/恢复必要的动态 shape 信息及随机数状态。
  • 提交 PR 前在单卡上完整跑通该 quickstart 脚本的几个 step，确保 loss 正常计算。
可能涉及的目录或文件
  • molt/trainer/fsdp/strategy.py
  • molt/trainer/sft_trainer.py
  • molt/models/
验收方式
  • 运行 `examples/scripts/quick_start/sft_qwen3_6_35b.sh` 至少 10 个 step，不抛出 `CheckpointError` 且 loss 正常下降。

风险

  • 涉及 PyTorch 底层的 autograd 和 checkpoint 机制，可能需要深入调试 C++ 引擎抛出的错误；可能与 AutoModel 的特定版本行为强耦合。

为什么值得长期做：DeepSeek-V4 是当前最受关注的模型，为其提供可靠的底层依赖（vLLM/FlashMLA/TE）编译与运行配方，能极大拓宽 Molt 的用户群体，并确立你在该项目环境与性能基建上的话语权。

怎么介入：这是一个开放的 Roadmap 讨论，没有 assignee，维护者尚未给出明确方案。作为社区专家介入，提供具体的单节点解决方案非常得体。
