modelscope/DiffSynth-Engine

候选人具备深厚的模型部署、分布式训练与底层架构经验。虽然当前受限于无 GPU 环境，但该项目中有大量纯逻辑层（权重加载、Mac MPS 适配、PyTorch 分布式 API 兼容性）的真实痛点。候选人可以利用 MacBook Air 完美复现和修复这些问题，展现工程素养。

当前方向：项目正处于快速扩展模型支持（Wan2.2, Qwen-Image, Flux）和多硬件后端（NPU, MPS）的阶段，同时在完善量化（GGUF）和分布式推理能力。

怎么介入这个项目

  • 环境准备：推荐使用 `pip install -e '.[dev]'` 和 `pre-commit install` 配置开发环境。
  • 沟通规范：在提交 PR 前，建议先在 Issue 下留言认领，说明修复思路，避免与内部开发计划冲突。
  • 测试要求：由于缺乏 CI 详情，提交前务必在本地（Mac/CPU）运行相关 Pipeline 的初始化和基础推理（可使用极小分辨率或 dummy weights）以验证逻辑正确性。
  • 联系方式：遇到深入架构的问题，可通过 README 提供的钉钉群或邮件 (muse@alibaba-inc.com) 与维护者沟通。

建议顺序

  • 修复 Mac MPS 环境下 Qwen-Image LoRA 加载崩溃问题
  • 修复 Wan2.2 GGUF 模型权重加载的 Shape 不匹配问题
  • 修复 PyTorch 2.9+ 分布式模块导入兼容性问题

成为长期维护者的路径
  • 从修复纯逻辑层的 Bug 和硬件适配入手，建立信任
  • 参与核心 Pipeline 的重构与参数暴露，提升 API 易用性
  • 未来有了 GPU 资源后，可深入参与 Triton/CUDA 算子优化与分布式推理 (Ring SP/Ulysses) 的核心开发

修复 Wan2.2 GGUF 模型权重加载的 Shape 不匹配问题

Issue #193 · May I ask if the gguf inference for wan2.2-i2v is supported? ↗

无人认领2 条评论更新 2025-11-05

用到的专长：模型量化部署（GGUF）与权重结构分析能力。

目标：修复 Wan2.2 I2V GGUF 模型在加载 `patch_embedding.weight` 时因通道数不匹配（36 vs 16）导致的崩溃。

为什么值得长期做：GGUF 量化支持是低显存设备运行大模型（如 Wan2.2 14B）的核心特性，修复此问题直接打通了 I2V 模型的端侧可用性。

怎么介入：Issue 开放，无 PR。维护者尚未回复，但属于明显的逻辑 Bug，适合直接提供修复。
第一个 PR 的边界：修复 Wan2.2 I2V GGUF 模型的初始化配置与权重加载逻辑。
第一步：对比 Wan2.2 T2V 和 I2V 模型的 `patch_embedding` 定义及配置解析逻辑。
认领留言（英文，可直接贴到 Issue）
Hi! The shape mismatch (36 vs 16) indicates the model is initializing the T2V `patch_embedding` instead of the I2V one. I can help fix the configuration parsing in `WanDiT` to correctly set the input channels when loading I2V GGUF weights. I'll test the state_dict loading on CPU and submit a PR. Let me know if you have any hints!
大致实施方案
  • 分析报错：I2V 模型的输入通道数通常比 T2V 多（因为需要拼接参考图像的 latent），导致 `patch_embedding` 权重 shape 不同（36 vs 16）。
  • 检查 `diffsynth_engine/models/wan/wan_dit.py` 中的模型初始化逻辑，确认是否在加载 I2V GGUF 时错误地使用了 T2V 的配置。
  • 修改配置解析或权重加载逻辑，确保当检测到 I2V 模型时，正确初始化 `in_channels` 为 36 的 `patch_embedding`。
  • 在 CPU 上编写脚本，仅加载 GGUF 权重到 Meta 设备或 CPU 内存，验证 `load_state_dict` 成功通过。
可能涉及的目录或文件
  • diffsynth_engine/models/wan/wan_dit.py
  • diffsynth_engine/pipelines/wan_video.py
验收方式
  • 在 CPU 上运行 Issue 提供的初始化代码，成功加载 GGUF 权重，不再抛出 `size mismatch` 异常。
开工前问题与风险

向维护者确认

  • Does the current `WanPipelineConfig` automatically distinguish between T2V and I2V models, or should we add an explicit flag to handle the `patch_embedding` channel difference?

  • GGUF 解析逻辑可能硬编码了某些 T2V 的参数，需要仔细排查其他潜在的 shape 不匹配。

为什么值得长期做：提升 Pipeline 的灵活性和用户体验，是构建易用推理引擎的基础。
