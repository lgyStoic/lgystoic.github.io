modelscope/DiffSynth-Engine

该仓库是高性能扩散模型推理引擎，高度契合候选人在 PyTorch 内部机制、模型部署、量化（GGUF）及端侧（Mac MPS）加速方面的专长。虽然候选人目前没有 GPU，但该项目大量涉及纯逻辑层的权重解析、分布式环境适配、API 封装以及 Mac 端的兼容性问题，非常适合在 Apple Silicon 上进行开发和验证。

当前方向：近期重点在于支持最新的视频/图像生成模型（Wan2.2, Qwen-Image），完善多平台（特别是 Mac MPS 和 NPU）的兼容性，以及优化底层 Attention 算子和量化加载逻辑。

无人认领2 条评论更新 2026-01-19

用到的专长：PyTorch 内部机制与模型架构操作

目标：修复在 Mac 上使用 QwenImagePipeline 加载 LoRA 时，因找不到 `diffusion_model` 属性导致的 AttributeError。

为什么值得长期做：端侧（Mac MPS）兼容性是该引擎的核心卖点之一。修复特定模型的 LoRA 加载问题能展现对 PyTorch 模块层级和引擎架构的深入理解，是成为核心维护者的绝佳切入点。

怎么介入：Issue 处于 Open 状态，无 Assignees，无关联 PR，且明确发生在 Mac 环境，非常适合认领。
第一个 PR 的边界：在 QwenImageDiT 或相关 Pipeline 中添加 10-20 行代码以正确映射模块属性。
第一步：检查 `diffsynth_engine/models/base.py` 中的 `load_loras` 方法以及 `QwenImageDiT` 的类定义，定位属性缺失的原因。

大致实施方案

  • 在 `QwenImageDiT` 类中添加 `diffusion_model` 属性（可能只需 `self.diffusion_model = self` 或指向正确的子模块），或者重写该模型的 LoRA 加载逻辑以适配其真实的模块结构。
  • 使用 Issue 中提供的测试脚本和一个 dummy LoRA 权重进行本地验证，确保不再抛出 AttributeError。

目标：解决加载 Wan2.2-I2V GGUF 模型时 `patch_embedding.weight` 的形状不匹配问题（5120x36x1x2x2 vs 5120x16x1x2x2）。

为什么值得长期做：GGUF 等量化格式的支持是 DiffSynth 的核心优势。解决复杂的多模态模型（I2V）权重映射问题，能证明候选人对 DiT 架构和量化部署的深刻理解。

第一个 PR 的边界：修改 `wan_video.py` 中的配置实例化逻辑，以及 `wan_dit.py` 中的通道数适配，约 30-50 行代码。
第一步：分析 `diffsynth_engine/models/wan/wan_dit.py` 中的模型初始化参数，对比 T2V 和 I2V 在输入通道数上的差异。
认领留言（英文，可直接贴到 Issue）

I will adjust the config initialization in `WanVideoPipeline` to correctly set the channels for I2V. I can submit a PR in 3 days. Is there any other I2V-specific config I should be aware of?
