modelscope/DiffSynth-Engine

DiffSynth-Engine 是一个高性能扩散模型推理引擎，强调无外部依赖的纯净实现和跨平台（包括 Apple Silicon）支持。候选人作为资深 PyTorch 内核与推理加速工程师，虽然当前没有 GPU，但可以完美胜任该引擎在 Mac/CPU 端的纯逻辑层修复、权重加载适配、分布式 API 兼容性处理以及服务端点封装等工作，充分发挥其在模型架构和端侧部署上的专长。

当前方向：近期仓库重点在于支持最新的视频/图像生成模型（如 Wan2.2-S2V, Qwen-Image-Edit, Flux.1）以及完善多硬件后端（如 NPU、Mac MPS）的兼容性和量化（GGUF/FP8）支持。

四、怎么介入这个项目

  • 开发环境准备：克隆源码后，务必运行 `pip install -e '.[dev]'` 和 `pre-commit install` 以配置开发依赖和代码格式化钩子。
  • 沟通渠道：遇到复杂设计问题，可通过 README 中提供的钉钉群二维码或发送邮件至 muse@alibaba-inc.com 与维护团队沟通。
  • 提交规范：项目采用 Apache 2.0 协议，提交 PR 前请确保代码在本地通过了 pre-commit 检查，并在 PR 描述中清晰说明测试环境（如 Apple Silicon Mac）。

建议顺序

  • 修复 Mac MPS 下 QwenImageDiT 加载 LoRA 时的属性错误
  • 修复 Wan2.2-I2V GGUF 权重加载时的 Patch Embedding 维度不匹配问题
  • 修复 PyTorch 2.9+ 下分布式张量并行 API 的导入错误
  • 提供基于 FastAPI 的批量推理服务端点示例
  • 审阅并验证 WanS2VDiT 的 attn_kwargs 传递修复
成为长期维护者的路径
  • 通过修复 Mac MPS 和 GGUF 加载等端侧痛点问题，建立在模型权重解析和跨平台兼容性方面的信任。
  • 逐步接手纯逻辑层的 Pipeline 抽象和 API 设计，为引擎的易用性和生产环境部署（如 FastAPI 集成）做出贡献。
  • 参与核心模型（如 Wan, Qwen-Image）的代码审阅，最终成为端侧推理和架构逻辑的核心维护者。
