sgl-project/sglang

SGLang 是一个追求极致性能的 LLM 与多模态推理框架。候选人具备深厚的 GPU Kernel、Triton、量化及扩散模型加速经验，与 SGLang 当前在底层算子优化（如 MLA、Cascade Attention）、多模态扩展（Diffusion）以及系统级显存管理（Hierarchical Cache）的核心演进方向完美契合。单卡算力足以完成这些模块的开发与验证。

当前方向：SGLang 目前正致力于前沿模型（如 DeepSeek-V4、GLM-5）的底层架构适配（如 NoPE MLA）、长上下文注意力优化、多模态/扩散模型支持，以及系统级缓存与调度机制的鲁棒性提升。

目标：优化 tilelang_sparse_fwd 内核的 shared memory 使用，移除无用的 O_shared 分配，确保在 SM120 (99KB 限制) 上成功运行 NoPE MLA。

怎么介入：Issue 处于 open 状态，无 assignee，无 linked PRs。非常适合直接认领。
第一个 PR 的边界：仅修改 TileLang kernel 的 shared memory 分配逻辑，不触及其他后端。

认领留言（英文，可直接贴到 Issue）
Hi, I'd like to look into this. I plan to optimize the shared memory usage in `tilelang_sparse_fwd` by removing the redundant `O_shared` allocation and tuning the tile sizes to fit within the 99KB limit of SM120. 大致实施方案
  • 审查 tilelang_kernel.py 中的 sparse_attention_fwd_kernel_v1 实现。
  • 移除 O_shared 的分配和 T.copy(acc_o, O_shared) 操作，直接将 acc_o 写入 Output。
  • 调整 block_I 或其他 tile size 参数，确保总 shared memory 占用严格低于 99KB。
  • 编译并使用 GLM-5.x 模型（配置 qk_rope_head_dim=0）进行单卡测试，验证输出正确性。
可能涉及的目录或文件

验收方式
  • 编写一个微测试，调用修改后的 kernel，断言其 shared memory 分配小于 99KB，且输出与 PyTorch 原生实现一致。
开工前问题与风险

向维护者确认

  • 是否有其他依赖 O_shared 的隐藏逻辑？
