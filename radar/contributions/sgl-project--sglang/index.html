sgl-project/sglang

候选人作为资深 GPU kernel 与训练性能工程师，虽然目前受限于无 GPU 环境，但 SGLang 作为一个高性能分布式推理框架，其调度器逻辑、分布式通信策略（TP/PP）、模型权重加载机制以及编译期缓存管理等纯逻辑层工作，完美契合候选人的系统工程能力。这些任务均可在 CPU/Mac 上完成开发与验证，为未来深入底层 kernel 优化打下坚实基础。

当前方向：SGLang 目前正致力于扩展对最新模型（如 DeepSeek-V4.1、Qwen3 等）的支持，优化分布式推理架构（如 P/D 分离、TP 通信优化），并完善生态兼容性（如对齐 vLLM 的 KV cache 事件、统一 JIT 缓存管理）。

为什么值得长期做：探索非对称的 Prefill/Decode 部署架构，大幅减少 Prefill 节点的显存占用，是提升大规模模型（如 DeepSeek-V4.1）分布式推理效率的前沿优化，极具挑战性。

怎么介入：Issue 开放且无 linked PRs，属于架构设计 RFC，适合资深工程师进行原型开发。

第一步：梳理当前的 P/D 分离逻辑（`python/sglang/srt/managers/`），分析如何将 prompt 截断并分配给不同的 worker。
认领留言（英文，可直接贴到 Issue）

大致实施方案
  • 在调度器中引入非对称 P/D 策略的配置开关。
  • 修改请求分发逻辑：当开启该策略时，将长度为 N 的 prompt 截断为 `N-W` 发送给 Prefill worker。
  • 修改 KV 传输逻辑，确保 `N-W` 的 KV 缓存正确传输到 Decode worker。
  • 在 Decode worker 侧，构造一个特殊的 bounded prefill 请求，包含最后 `W` 个 token 和接收到的前缀 KV。
  • 调整模型加载逻辑，允许 Prefill worker 仅加载部分层（如 L0-L19 和 L20 的投影层）。
