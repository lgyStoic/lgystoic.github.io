为什么值得长期做：权重加载逻辑是模型推理的入口。解决不同配置下的权重兼容性问题，能显著提升用户体验，展现对 PyTorch 模型结构的深刻理解。

怎么介入：Issue 是最近提出的 bug，无 assignee，适合快速修复。
第一个 PR 的边界：在推理脚本或模型加载工具函数中添加针对 `original` attention 的权重过滤逻辑。
第一步：在 `turbodiffusion/inference/wan2.2_i2v_infer.py` 或模型初始化代码中，定位 `load_state_dict` 的调用位置。

用到的专长：分布式训练性能与 PyTorch 内核

目标：解决训练脚本中 `checkpoint_wrapper` 抛出的 `NotImplementedError`，使模型能够正常进行前向和反向传播。

为什么值得长期做：Activation Checkpointing 是大模型训练的核心技术。修复相关的底层报错，能展现候选人在分布式训练和 PyTorch 底层机制上的深厚功底。

怎么介入：Issue 处于 open 状态，报错信息明确，无 assignee，适合深入排查。
第一个 PR 的边界：修复 `wan2pt1.py` 中 activation checkpointing 的参数传递逻辑。
第一步：查看 `turbodiffusion/rcm/networks/wan2pt1.py` 中 `block` 的 `forward` 方法签名，以及 `checkpoint_wrapper` 的使用方式。
认领留言（英文，可直接贴到 Issue）
Hi, I'd like to investigate this `NotImplementedError`. It usually occurs when `torch.utils.checkpoint` receives unsupported kwargs or when `use_reentrant` behavior mismatches. I will reproduce this locally with a dummy forward pass and propose a fix, likely by adjusting how arguments are passed to the checkpointed block. I can provide a PR within 3 days.
大致实施方案
  • 在 CPU 上编写一个极简的单测，实例化 `wan2pt1` 模型并启用 selective checkpointing，传入 dummy tensor 触发 forward。
  • 复现 `NotImplementedError`。通常这是因为 `checkpoint_wrapper` 内部的 `checkpoint` 函数不支持某些类型的 kwargs，或者 kwargs 中包含了不可求导的复杂对象。
  • 修改 `wan2pt1.py` 中 `block` 的调用方式，尽量将 kwargs 转换为位置参数（args），或者在包装 checkpoint 时使用 `use_reentrant=False`（如果是 PyTorch 较新版本）。
  • 运行单测，确认 forward 和 backward 都能成功执行。
可能涉及的目录或文件

  • turbodiffusion/rcm/models/t2v_model_distill_rcm.py

向维护者确认
