修复 16GB 内存环境下的多进程模型加载 OOM 问题

Issue #1755 · Quickstart example OOMs on 16GB-RAM free-tier environments (Kaggle, Colab) ↗

无人认领1 条评论installationperformancescope: attention更新 2026-08-25

用到的专长：利用深厚的系统级内存管理经验，解决多进程架构下的内存峰值问题。

目标：消除 MultiProcExecutor 在移交 worker 时的内存双倍占用峰值，使 1.3B 模型能在 16GB 系统 RAM 环境下成功加载。

为什么值得长期做：内存峰值管理是推理框架的核心竞争力。解决此问题能大幅降低 FastVideo 的体验门槛，让免费层用户也能顺利运行，直接提升项目的普及率。

怎么介入：Issue 处于 open 状态，无 assignee 且无 linked PR，非常适合直接认领并主导修复。
第一个 PR 的边界：仅修改 MultiProcExecutor 的初始化与模型移交逻辑，确保主进程及时释放内存。
第一步：在 Colab T4 免费实例上复现 OOM，定位主进程与子进程在 handoff 期间对模型权重的引用持有情况。
认领留言（英文，可直接贴到 Issue）
Hi, I'd like to look into this OOM issue. I suspect the memory spike happens because both the main process and the worker hold references to the model during the handoff in `MultiProcExecutor`. I plan to test a fix on a 16GB Colab instance by ensuring the main process releases the weights properly. I can submit a PR within a few days.
大致实施方案
  • 在 Colab T4 (16GB RAM) 上运行 README 中的 Quickstart 代码，确认在 MultiProcExecutor 初始化时发生 OOM。
  • 审查 `fastvideo/worker/multiproc_executor.py`，分析 `worker_busy_loop` 和进程 spawn/fork 时的内存状态。
  • 修改逻辑，确保主进程在将模型移交给 worker 后，立即释放其在主进程中的内存引用（或采用更高效的共享内存按需加载机制）。
  • 测试修复方案，确保在 16GB RAM 限制下，模型加载和推理均能顺利完成。
可能涉及的目录或文件
  • fastvideo/worker/multiproc_executor.py
  • fastvideo/models/loader/
验收方式
  • 在 16GB RAM 的 Colab T4 实例上运行 `VideoGenerator.from_pretrained("FastVideo/FastWan2.1-T2V-1.3B-Diffusers", num_gpus=1)`，确保不触发 OOM 且能成功生成。
开工前问题与风险

向维护者确认

  • Is there a preferred strategy for the handoff? Should the main process explicitly delete the model reference and call garbage collection, or should we refactor the loader to only instantiate the model inside the worker process?

风险

  • 修改多进程生命周期可能引发死锁或在其他后端（如 MPS）上产生意外的序列化问题。

为什么值得长期做：量化与 LoRA 的结合是当前高效推理的前沿需求。完善这一生命周期管理能让 FastVideo 的量化方案真正具备生产可用性。

第一个 PR 的边界：移除 #1796 的拦截逻辑，替换为完整的 BF16 恢复与重新量化实现，并附带 CPU 测试。
第一步：阅读 PR #1796 中关于拒绝 MXFP8/NVFP4 LoRA 操作的拦截逻辑，设计 BF16 权重缓存与重新量化机制。

目标：引入 `FASTVIDEO_KERNEL_BUILD_EXTENSION=OFF` 环境变量，允许用户跳过 C++/CUDA/HIP 扩展编译，仅安装 Python 和 Triton 模块。

大致实施方案
