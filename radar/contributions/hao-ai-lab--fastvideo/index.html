一、项目定位

FastVideo 是一个专注于视频生成模型（DiT）的端到端后训练与实时推理加速框架。它不仅提供 DMD2 蒸馏、Attn-QAT 量化等训练方案，还通过序列并行（Sequence Parallelism）和多种稀疏注意力机制（如 Video Sparse Attention）将推理速度提升数十倍，甚至支撑了实时视频生成应用 Dreamverse。对于你这位资深 GPU 性能工程师，这个项目极其契合你的技术栈（CUDA、算子融合、量化、分布式）。针对你目前只有一台 16GB MacBook Air 的硬约束，FastVideo 提供了完美的切入环境：首先，其 pyproject.toml 中明确将 CUDA 依赖（flashinfer-python、fastvideo-kernel）通过 sys_platform == 'linux' 进行了隔离，保证了 Mac 上的顺利安装；其次，仓库内包含专门的 fastvideo/mlx_runtime 目录，并官方发布了针对 Mac 优化的 FastMetal-QAD 模型。这意味着你可以直接在本地开展 Apple Silicon (MLX) 的端侧推理加速与算子开发，或者进行框架层的序列并行逻辑重构。对于必须写 CUDA/Triton 算子的场景，其核心算子库完全独立在 fastvideo-kernel 目录下，你可以本地编写 C++/CUDA 代码，利用 Colab 的免费 T4 实例进行几十分钟的编译与正确性验证，最后依赖项目完善的 CI（Buildkite/GitHub Actions）完成性能回归测试。项目目前处于高速迭代期，已发布 v0.2.1 版本。

解决什么问题、给谁用

解决视频生成大模型（如 Wan、MiniMax-H3）计算复杂度极高、显存占用大，导致难以实现实时生成（Real-time Generation）和端侧部署的问题。目标用户包括：需要对开源视频模型进行微调与蒸馏（DMD2）的 AI 研究员；追求极致推理速度与显存优化的底层性能工程师；以及构建实时视频交互应用（如 Vibe Directing）的业务开发者。典型场景包括单卡 4.5 秒生成 1080p 视频、Mac 端侧本地视频生成，以及大规模集群上的序列并行推理。

AI 研究员（模型蒸馏与微调）、底层性能工程师（算子优化与分布式推理）、AI 应用开发者（实时视频生成服务）。

同类项目与差别

  • diffusers：FastVideo 依赖 diffusers，但 diffusers 偏向通用的模型加载与基础推理，FastVideo 则专注于视频 DiT 的极致性能优化，提供了 diffusers 缺乏的视频稀疏注意力（VSA）、序列并行和端到端蒸馏流水线。
  • vLLM / SGLang：vLLM 等框架主要针对 LLM（文本）的 KV Cache 和 PagedAttention 优化，而 FastVideo 填补了视频生成（时空注意力机制）领域的推理加速空白。
  • FlashInfer：FastVideo 在 Linux 平台底层依赖 FlashInfer，但在此之上构建了更复杂的视频专属注意力后端（如 Sliding Tile Attention 和 Video Sparse Attention），并提供了完整的训练/推理上下文。

二、架构与代码地图

针对你目前只有一台 MacBook Air (Apple Silicon, 16GB) 的硬约束，FastVideo 的架构设计对你极其友好。它的核心设计理念是「控制面与数据面分离」以及「硬件依赖严格隔离」。整个项目自上而下可以清晰地分为五层： 1. 应用与入口层 (Application & Entry Layer)：包含 apps/dreamverse/（实时视频流应用）和 fastvideo/api/、fastvideo/entrypoints/。这里定义了对外的 REST API、CLI 入口以及核心的 VideoGenerator 类。所有的请求配置（如 GenerationRequest）都在这里完成解析与校验。 2. 调度与执行层 (Scheduling & Execution Layer)：位于 fastvideo/pipelines/ 和 fastvideo/distributed/。这里是分布式推理和训练的大脑，负责处理 Sequence Parallelism (SP)、FSDP2 以及 DMD2 蒸馏的 pipeline 编排。对于你来说，如果要在 Mac 上重构分布式通信逻辑的 mock 或调度策略，这里是主战场。 3. 模型与算子桥接层 (Model & Operator Bridge Layer)：位于 fastvideo/models/ 和 fastvideo/attention/backends/。这是极其优雅的一层，它将上层的 Transformer/DiT Block 与底层的硬件算子解耦。系统会根据运行环境动态路由到 FlashAttention、SageAttention、QAT 算子或 MLX 后端。 4. Apple Silicon 运行时 (MLX Runtime Layer)：位于 fastvideo/mlx_runtime/。这是你本地开发的核心乐园！FastVideo 官方支持了 FastMetal-QAD 模型，这意味着在没有 CUDA 的情况下，你可以直接在这个目录下利用 Apple MLX 框架进行端侧推理加速、量化验证和算子开发，完全不需要依赖远程 GPU。 5. 底层 Kernel 层 (Low-level Kernel Layer)：完全独立在 fastvideo-kernel/ 目录下。这里包含了所有的 C++/CUDA 和 Triton 算子（如 attn_qat_infer、block_sparse_sm100a.cu、turbodiffusion）。pyproject.toml 中通过 sys_platform == 'linux' 完美隔离了它的安装。你可以在 Mac 上用 VSCode 编写这里的 CUDA/Triton 代码，然后推送到 Colab 的免费 T4 实例上，运行 cd fastvideo-kernel && ./build.sh 进行几十分钟的编译和正确性验证，最后交由 CI 完成性能回归。

一次调用怎么流过这些模块

在 FastVideo 中，一次视频生成请求的数据流设计极其精巧，特别是它针对不同硬件（如你的 Mac 与生产环境的 Linux/GPU）做了优雅的分流。以下是完整的端到端路径： 1. 请求初始化与解析 (API Layer)： 用户通过 CLI 或 apps/dreamverse 发起请求。请求首先进入 fastvideo/api/schema.py，被解析为强类型的 GenerationRequest 和 PipelineConfig。此时，系统会根据环境变量（如 FASTVIDEO_ATTENTION_BACKEND）和硬件探测结果决定后续的执行策略。 2. 硬件路由与环境隔离 (The Mac Fork)： 这是对你最关键的一步。如果系统探测到运行在 Apple Silicon 上，pyproject.toml 的依赖隔离机制会确保不加载 CUDA 库。数据流会被路由到 fastvideo/mlx_runtime/。在这里，模型权重（如 FastMetal-QAD）会被加载为 MLX Tensor，后续所有的计算图构建和执行都在 CPU/GPU 共享内存的统一架构下完成。如果是在 Linux/CUDA 环境下，系统则会初始化 fastvideo/distributed/，建立通信组以支持 Sequence Parallelism。 3. Pipeline 调度与去噪循环 (Pipeline Layer)： 进入 fastvideo/pipelines/ 后，系统开始执行 DiT（如 Wan2.1 或 MiniMax-H3）的去噪循环。对于 DMD2 蒸馏模型，可能只需要 4-8 步（如 FastH3 8-Step V2）。在每一步中，隐变量（Latents）被送入 Transformer Blocks。 4. 注意力机制分发 (Attention Dispatch)： 在 fastvideo/models/ 的 Transformer Block 中，当需要计算 Attention 时，数据流进入 fastvideo/attention/backends/。抽象基类 abstract.py 会根据配置调用具体的后端。例如，如果启用了 QAT（量化感知训练）推理，它会路由到 attn_qat_infer.py。 5. 底层 Kernel 执行 (Kernel Layer)： 在 CUDA 环境下，Python 会通过 pybind11 或 Triton JIT 调用 fastvideo-kernel。例如，Triton 算子 group_mean_kernel（位于 fastvideo-kernel/attn_qat_infer/api.py）会对 Query 进行分组求均值预处理；随后，高度优化的 C++/CuTe 算子（如 block_sparse_sm100a.cu）会在 GPU 显存中完成极速的稀疏矩阵乘法。你可以在 Colab 上验证这一步的数据正确性。 6. 解码与输出 (Output Layer)： 去噪完成后，隐变量通过 VAE 解码为像素空间数据，交由 fastvideo/image_processor.py 处理，最终编码为 MP4 文件，或通过 apps/dreamverse/dreamverse/av_streaming.py 以 WebRTC 视频流的形式实时推给前端用户。

三、本地跑起来（没有 GPU 的 Mac）

安装

  1. uv venv --python 3.12 --seed
  2. source .venv/bin/activate
  3. uv pip install -e '.[mlx]'
  4. pre-commit install --hook-type pre-commit --hook-type commit-msg

哪些路径能真跑

由于你目前只有 MacBook Air，核心的 C++/CUDA 算子（位于 fastvideo-kernel/ 目录，如 block_sparse_sm100a.cu、attn_qat_infer）以及 fastvideo/attention/backends/ 下的 FlashAttention/SageAttention 路由只能阅读源码，或在 Colab T4 上短暂编译验证。但项目对 Mac 极其友好：你可以在 fastvideo/mlx_runtime/ 目录下进行 Apple Silicon (MLX) 的端侧推理加速与算子开发；此外，apps/dreamverse/mock_server.py 和 apps/fastvideo_studio/mock_server.py 提供了纯内存的 Mock Server，完全无需 GPU 即可在本地进行分布式调度逻辑或上层 API 的重构与调试。

测试

测试框架使用 pytest。顶层测试位于 tests/，包级别测试位于 fastvideo/tests/，本地组件测试位于 tests/local_tests/。在 Mac 上，建议运行 pytest fastvideo/tests/ -v --ignore=fastvideo/tests/ssim/ 来执行 CPU 子集，因为 AGENTS.md 明确指出 ssim/ 目录包含重度依赖 GPU 的图像质量回归测试。代码规范检查必须通过 pre-commit run --all-files 执行。

调试

  • 环境变量：通过设置 os.environ['FASTVIDEO_ATTENTION_BACKEND'] = 'MLX' 或 'VIDEO_SPARSE_ATTN' 强制切换注意力后端进行本地调试。
  • 日志与断点：项目集成了 loguru 和 remote-pdb（见 pyproject.toml），可在分布式调度（如 fastvideo/distributed/）中插入 remote_pdb.set_trace() 进行跨进程断点。
  • 性能分析：入口位于 fastvideo/profiler.py，可通过运行 examples/inference/basic/basic_fasth3_simplified_profile.py 快速拉起端到端 Profiling。

CI

项目采用双轨 CI：重度性能基准测试与 GPU Pipeline 运行在 Buildkite 上（见 .buildkite/ 目录），而常规的代码检查与文档构建（如 infra-docs.yml）运行在 GitHub Actions 上。你的 PR 最容易被 pre-commit 钩子（yapf, ruff, mypy, codespell）卡住，必须在本地通过检查。

坑

  • 千万不要在 Mac 上强行安装 fastvideo-kernel 或 flashinfer-python。pyproject.toml 中已通过 sys_platform == 'linux' 优雅隔离了这些强依赖 nvcc 的包，强装会导致 CMake 编译报错。
  • 不要直接使用 yapf/ruff/mypy 命令行扫描全库。AGENTS.md 明确警告必须使用 pre-commit run，因为它配置了严格的 excludes（例如 fastvideo/tests/ 被故意跳过），绕过 pre-commit 会导致大量误报。
  • 在 Mac 上跑全量 pytest 时，务必跳过 fastvideo/tests/ssim/，否则会因为缺少 CUDA 环境导致测试直接崩溃。
