THU-MIG/edge-dit.cpp

候选人具备深厚的底层算子与性能优化经验。虽然受限于当前无 GPU 硬件，但项目本身是基于 ggml 的 C/C++ 推理引擎，强调跨平台与端侧部署。候选人可以利用 Mac 环境，在 CPU/Metal 后端进行性能建模、算子 fallback 分析、内存调度逻辑验证以及测试基建，完美契合项目对资源受限设备优化的核心诉求。

当前方向：项目正处于 Alpha 阶段，快速扩展对各类前沿 DiT 模型（如 FLUX, Wan 2.1, MiniMax-H3, LTX-2.3）的支持，同时致力于完善多后端（CUDA, CPU, Vulkan, Metal）的兼容性与显存/内存优化（如自动量化、分层 offload）。

怎么介入这个项目

  • 提交性能相关的 PR 时，必须在描述中包含：使用的模型系列与命令行、硬件信息、before/after 的延迟或内存数据，以及正确性/图像质量验证结果。
  • Python 层的验证需在 `bindings/python` 目录下执行 `python -m pip install -e '.[dev]'` 并运行 `pytest`。
  • 真实模型的集成测试需显式依赖环境变量（如 `EDGE_DIT_RUN_INTEGRATION=1`），切勿将其加入常规的默认开发或 CI 流程中。
  • 代码风格上需优先使用项目现有的抽象模式，隔离模型特定的优化，且严禁提交本地生成的图像、视频、日志或模型权重文件。

验证并优化 LTX-2.3 在 Apple Silicon (Metal/CPU) 上的推理性能与正确性

Issue #82 · [Feature]: LTX2.3 ↗

无人认领0 条评论enhancement更新 2026-08-20

用到的专长：性能建模与 roofline 分析、构建系统与多后端适配、测试基建。

目标：验证最近合并的 LTX-2.3 管道在 Mac (CPU/Metal) 上的正确性，补充缺失的集成测试，并进行初步的性能 profiling。

为什么值得长期做：随着新模型（如 LTX-2.3）的快速集成，确保其在非 CUDA 后端（如 CPU 和 Metal）上的正确性和性能是跨平台推理引擎的核心价值。通过接手新模型的跨平台验证与性能分析，可以快速建立对项目架构（ggml 后端、图执行、内存分配）的深入理解，为后续主导核心算子优化或调度逻辑打下基础。

怎么介入：Issue #82 仍处于 open 状态，但主分支最近已有多个关于 LTX-2.3 的 commit（如 `feat(ltx): add LTX-2.3 video and audio pipeline`）。核心功能已实现，直接提交功能 PR 不得体。建议通过补充 Mac/CPU 验证、性能分析和集成测试来介入。
第一个 PR 的边界：补充 LTX-2.3 的 Python 集成测试，并可能包含针对 Mac 编译/运行的小修复。
第一步：编译 CPU/Metal 版本，运行 LTX-2.3 模型，记录性能瓶颈并向维护者汇报。
认领留言（英文，可直接贴到 Issue）
Hi! I see LTX-2.3 support was recently merged into main. Since I'm currently working on an Apple Silicon Mac, I'd love to help validate its correctness on CPU/Metal backends, profile the performance to identify any operator fallbacks, and add the missing integration tests. Would it be helpful if I submit a PR with the tests and a brief performance report for macOS within a few days?
大致实施方案
  • 拉取最新 `main` 分支，按照 `scripts/build_cpu.sh` 编译 CPU 版本（或尝试启用 Metal 编译）。
  • 下载 LTX-2.3 模型权重，使用 `ed-cli` 运行推理，结合 `--auto-fit` 确保在 16GB Mac 上不 OOM，验证输出的正确性。
  • 使用 Instruments 或 ggml 内置的 profiling 工具分析 LTX-2.3 在 Mac 上的性能瓶颈（如特定算子未命中 Metal 优化路径而 fallback 到 CPU）。
  • 编写针对 LTX-2.3 的 Python 集成测试脚本（参考 `bindings/python/tests`），通过设置 `EDGE_DIT_RUN_INTEGRATION=1` 运行。
  • 提交 PR 补充测试，并在 PR 描述中附带 Mac 上的性能分析报告。
可能涉及的目录或文件
  • bindings/python/tests
  • src/
验收方式
  • 在 Mac 上成功编译并运行 LTX-2.3 模型，输出合理的视频/音频结果。
  • 运行 `pytest` 且新增的 LTX-2.3 集成测试通过。
开工前问题与风险

向维护者确认

  • I noticed LTX-2.3 support was recently merged. Are there any specific Metal/CPU operators for LTX-2.3 that you suspect might be unoptimized or falling back?
  • Should I add the LTX-2.3 integration tests to the existing Python test suite under `bindings/python`?

风险

  • Metal 后端目前处于 Experimental 阶段，可能会遇到 ggml 层面的算子不支持问题。
  • LTX-2.3 模型可能较大，16GB 内存的 Mac 可能需要配置适当的 offload 或量化参数 (`--auto-fit`) 才能运行。
