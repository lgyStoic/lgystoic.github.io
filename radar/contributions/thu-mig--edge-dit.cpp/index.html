THU-MIG/edge-dit.cpp

候选人是资深 GPU/性能工程师，但目前受限于无 GPU 硬件。edge-dit.cpp 是纯 C/C++ 的 ggml 架构推理引擎，支持 CPU 和 Metal 后端。候选人可以在 Mac 上发挥对计算图、算子逻辑和内存管理的专长，通过代码审查、补充测试和纯逻辑层的优化来贡献。

当前方向：项目处于 Alpha 阶段，近期重点是支持更多 DiT 模型（如 MiniMax-H3, LTX-2.3），优化显存占用（auto-fit, offload），以及完善多后端（CUDA, CPU, Metal, Vulkan）的支持。

为 LTX-2.3 新增功能补充 CPU/Mac 单元测试与代码审查

Issue #82 · [Feature]: LTX2.3 ↗

无人认领0 条评论enhancement更新 2026-08-20

用到的专长：利用性能工程师对计算图和算子逻辑的敏感度，审查新模型的执行路径并补充测试。

目标：审查最近合并的 LTX-2.3 相关 commits，并在 Mac/CPU 环境下补充相应的单元测试或集成测试，确保其在非 CUDA 后端的基础逻辑正确性。

为什么值得长期做：通过为新合并的复杂模型（LTX-2.3）编写测试和审查代码，可以快速熟悉 edge-dit.cpp 的底层 ggml 算子调用和内存管理机制，为后续深入参与核心架构优化和多后端适配打下基础。

怎么介入：主分支最近的 commits（如 `feat(ltx): add LTX-2.3...`）表明该功能已被实现。直接认领开发不得体。建议通过补充测试和代码审查来介入。
第一个 PR 的边界：新增针对 LTX-2.3 图构建或特定算子的 C++ 单元测试，不修改核心业务逻辑。
第一步：在 Issue #82 下留言，指出已看到相关 commits，并询问是否需要补充 Mac/CPU 端的测试或进行代码 review。
认领留言（英文，可直接贴到 Issue）
I noticed the recent commits adding LTX-2.3 support. Since the core feature seems implemented, I'd love to help review the changes and add unit tests for the CPU/Metal paths on Apple Silicon to ensure cross-backend stability. Would you welcome a PR focusing on test coverage for this?
大致实施方案
  • 拉取最新主分支代码，在 Mac 上使用 `bash ./scripts/build_cpu.sh` 编译项目。
  • 审查 `feat(ltx)` 和 `perf(ltx)` 相关的 commits，理解 LTX-2.3 的模型加载、内存分配和执行图构建逻辑。
  • 编写针对 LTX-2.3 特定算子或图构建逻辑的 C++ 单元测试，确保在 CPU 后端（ggml）上的数值正确性。
  • 运行 Python 绑定测试 `pytest`，并在本地验证测试通过。
  • 提交 PR，并在 PR 描述中说明这是对 LTX-2.3 功能的测试补充。
可能涉及的目录或文件
  • src/
  • tests/
  • bindings/python/
验收方式
  • 在 Mac 上运行 `bash ./scripts/build_cpu.sh` 编译成功。
  • 运行新增的单元测试并全部通过。
开工前问题与风险

向维护者确认

  • I noticed that LTX-2.3 support has been recently merged. Do you need any help with adding unit tests or verifying the CPU/Metal fallback paths on Apple Silicon?
  • Are there any specific edge cases in the LTX-2.3 implementation that require additional test coverage?

风险

  • LTX-2.3 模型可能过大，无法在 16GB Mac 上进行端到端集成测试，只能进行算子级别或 mock 数据的单元测试。
