THU-MIG/edge-dit.cpp

候选人作为资深性能工程师，虽然当前受限于无 GPU 环境，但可以利用 Mac 充分发挥在数值正确性、性能建模（Roofline）、端侧部署（Metal/ARM CPU）以及系统级架构审查方面的专长。edge-dit.cpp 作为一个主打端侧和资源受限设备的 C++ 推理引擎，非常需要针对 Apple Silicon 的深度验证与性能基线建设。

当前方向：项目近期密集发布了对多种前沿 DiT 模型（如 MiniMax-H3, LTX-2.3）的支持，并完善了量化（ed-convert）和显存管理（auto-fit）。当前正处于功能快速扩张期，急需巩固非 CUDA 后端（CPU/Metal）的稳定性、正确性测试以及性能基线。

怎么介入这个项目

  • 开发前使用 `bash ./scripts/build_cpu.sh` 进行便携式基线构建，确保基础功能正常。
  • 提交 PR 时必须保持专注；如果是性能相关的修改，必须在 PR 描述中包含模型系列、命令行参数、硬件信息以及修改前后的延迟/内存对比数据。
  • 涉及公共行为的变更（如新增脚本、修改 API），必须在同一个 PR 中同步更新 README 或 docs。
  • 代码风格上，优先遵循项目现有的抽象模式，除非具有明显的复用价值，否则应将模型特定的优化隔离开来。
  • 切勿在 PR 中提交生成的输出文件、本地基准测试图像/视频、日志或机器特定的路径，也不要包含模型权重。

建议顺序

  • 为 LTX-2.3 补充 CPU/Metal 后端的正确性验证与文档
  • 构建 CPU/Metal 后端的 Roofline 性能分析工具
  • 验证并优化 `ed-convert` 量化模型在 Apple Silicon 上的推理精度
  • 为 Python 绑定添加基于 CPU 的轻量级 CI 集成测试
  • 审查并优化 Apple Silicon 上的统一内存分配策略
成为长期维护者的路径
  • 首先通过补充新模型（LTX-2.3）在 Mac 上的测试与文档，熟悉项目的构建系统与多后端执行流程。
  • 接着引入性能分析工具（Roofline）和量化精度基线，展现资深性能工程师的专业素养，帮助维护者建立科学的优化指标。
  • 最后深入核心的内存管理逻辑，针对 Apple Silicon 的统一内存架构提出系统级优化，逐步成为端侧架构设计的核心贡献者。

Proposal: Optimize Unified Memory Allocation for Apple Silicon

Since edge-dit.cpp emphasizes VRAM-aware placement, I'd like to review and optimize how memory is handled on Apple Silicon's unified memory architecture. The goal is to ensure `--auto-fit` and offloading logic don't unnecessarily treat CPU and GPU memory as separate pools on Macs, potentially reducing overhead and avoiding unnecessary swaps.   • 编写测试脚本，监控大模型（如 FLUX.1）在 Mac 上的内存占用和 swap 情况。
  • 提出修改方案，例如在 Metal 后端下共享 CPU/GPU 内存池，减少不必要的拷贝或 offload。
