无人认领0 条评论pipelinesfeature-request更新 2026-09-15

用到的专长：构建系统、纯逻辑层与安全基建。

目标：在 `from_pretrained` 中添加可选的哈希校验机制，防止加载被篡改的权重。

为什么值得长期做：涉及模型加载的核心路径，属于高级安全基建，能够展示系统级设计能力。

怎么介入：Issue 是一个 Feature Request，无 assignee，无 linked PR。作者提出了很好的设计，适合资深工程师接手实现。
第一个 PR 的边界：在加载路径中添加可选的哈希校验逻辑及相关测试。
第一步：梳理 `from_pretrained` 的调用链路，找到实际读取权重文件的切入点。
认领留言（英文，可直接贴到 Issue）
Hello! This is a great security feature. I'd love to implement the opt-in integrity verification. I plan to add an `expected_hashes` kwarg to `from_pretrained` that computes the SHA-256 of the weight files right before materialization, raising a clear error on mismatch. I will ensure default behavior and load times remain completely unaffected. I'll ask for your review on the API design in the PR.
大致实施方案
  • 在 `DiffusionPipeline.from_pretrained` 和 `ModelMixin.from_pretrained` 中添加 `expected_hashes` 或 `integrity_manifest` 参数。
  • 在实际调用 `safetensors.safe_open` 或 `torch.load` 之前，计算文件的 SHA-256。
  • 如果哈希不匹配，抛出明确的异常。
  • 优化性能：可以在流式读取时计算哈希，或者利用现有的缓存机制。
  • 编写测试：构造一个被篡改的 safetensors 文件，验证是否能被正确拦截。

  • src/diffusers/models/modeling_utils.py
验收方式
  • 编写单元测试，传入正确的哈希应成功加载，传入错误的哈希或修改文件内容应抛出异常。
开工前问题与风险

向维护者确认
