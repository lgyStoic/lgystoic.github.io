成为核心贡献者

从真实 Issue、提交和 Release 信号出发，规划 30 / 60 / 90 天贡献路线。目标是承担持续维护责任，而不是堆 PR 数量。

针对候选人具备 AI Infra、DiT、端侧部署及加速背景但缺乏高性能 GPU 的现状，核心策略是“以基础设施、跨平台支持和工程质量为切入点，逐步接管核心模块”。候选人应优先选择对 CPU/Mac/边缘设备友好、急需 CI/CD 稳定、内存优化或架构重构的项目。通过承担 issue triage、代码审查、静态分析、测试覆盖率提升和发布管理等高价值但低算力需求的维护工作，建立信任。待获取 GPU 资源后，再平滑过渡到核心算子优化和分布式训练/推理加速。

sgl-project/sglang

★ 36088 · Issue/PR 5383

匹配度：高度契合 AI Infra 和推理加速方向。项目正处于快速扩张期，多后端（Apple Silicon, NPU, XPU）和多模态（Diffusion）支持需求大，非常适合端侧部署和无高端 GPU 的候选人切入。

当前方向：根据近期活动推断，核心 roadmap 包括：1. 投机解码的持续演进（DFlash, Spec V2, Triton 验证）；2. 扩展硬件后端（TPU, AMD, XPU, NPU, Apple Silicon）；3. 大规模专家并行（DeepSeek V3/R1/V4）与弹性扩展（elastic-ep）；4. 多模态与 Diffusion 模型支持（FLUX.2）。

无 GPU / 低算力可选入口

  • 修复和稳定 CI 测试流水线（Issue #17050）
  • 完善 Apple Silicon (Mac) 后端的测试与文档
  • 实现 Triton 投机验证的运行时 token 宽度逻辑（PR #39859，可通过 Mock 或 CPU 验证逻辑）
  • 限制 SafeUnpickler 的标准库全局变量以提升安全性（PR #39858）
  • NPU/XPU 相关的代码逻辑审查与接口一致性维护
需要 GPU 后再考虑
  • DeepSeek V4/R1 的大规模专家并行（EP）优化
  • AMD gfx950 上的 FP8 和 MXFP4 服务端点支持
  • elastic-ep 的 CUDA Graph 捕获与扩展（PR #33723, #39834）

30 天

  • 通读架构文档，认领并修复 2-3 个 CI 相关的 Bug（如 #17050）
  • 复现并 Triage 至少 10 个新 Issue，补充复现脚本
  • 提交关于 SafeUnpickler 或前端路由（sgl-router）的改进 PR

60 天

  • 成为 Apple Silicon 或 NPU/XPU 接口层面的活跃 Reviewer
  • 主导一个非 GPU 核心模块的重构或测试覆盖率提升
  • 协助维护者进行 Release 前的回归测试

90 天

  • 获得 Triage 权限，主导 Issue 模块的日常管理
  • 参与核心调度或投机解码逻辑的架构讨论与 Review
  • 独立负责次要版本（Patch Release）的发布流程
维护者信号与风险
  • 主动接管并修复长期存在的 CI 测试失败问题
  • 为非 NVIDIA 后端（如 Apple Silicon, NPU）的 PR 提供高质量 Code Review
  • 规范化 Issue 标签管理，主动复现并分类用户提交的 Bug
  • 项目迭代极快，代码冲突频繁，需保持高频同步
  • 核心性能优化高度依赖高端 GPU 集群，短期内难以直接参与
